# 组合模板独立步骤与组合入口修复

日期：2026-08-31。状态：本地实现、自动化验证完成，未部署，未修改远程 D1。

## 业务规则

量体保持为步骤，分别在单品和组合模板中配置；不新增独立量体模板。

组合模板可以同时包含组合入口、独立选项、量体和确认步骤。“组合/套装”类型是子模板的展开位置，仅该类型要求恰好一个启用步骤，避免组件重复展开；不是限制整个流程只能有一个步骤。组合模板使用自身量体定义，不重复展示子模板的量体。

## 问题与修复

原后台切换组合类型时只更新模板类型和品类，没有自动建立组合入口；缺少与重复入口共用一条错误，容易误认为独立步骤不被支持。

- 切换组合类型自动补齐入口，默认放在已有步骤之前；已有停用入口则启用，保留已有配置与顺序，不重复创建。
- 定制步骤页增加“补齐组合步骤”按钮及规则说明，修复已有缺少入口的草稿；多个入口时明确提示只停用多余入口，不影响其他类型步骤。
- 切回单品时清理仅用于组合的入口与组件定义，保留普通选项、量体和确认步骤。
- 发布校验分别提示缺少入口／入口重复，不放宽对子模板的已发布状态与品类检查。

修改位于 MTM 后台的 `app/config-admin.tsx`、`app/admin/template-steps.tsx`、`src/domain/composite-flow.ts`、`src/services/template-service.ts`；回归测试为 `tests/composite-flow.test.mjs`。无数据库结构、API 结构、Shopify 权限或环境变量变更。

## 验证与上线

`npm run test:unit` 的 10 项测试通过，包含组合入口与其他三种独立步骤共同发布、缺失／重复入口拒绝、修复幂等及编码冲突处理。`npm run lint`、`npm test` 生产构建、`git diff --check` 均通过。

部署后，在已有组合模板的“定制步骤”页点击“补齐组合步骤”，按业务需要调整位置，再保存并发布。也可以在旧后台直接添加一个“组合/套装”类型步骤并启用，无需删除已有量体步骤。
