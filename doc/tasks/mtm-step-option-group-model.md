# MTM 步骤、选项组与选项模型改造任务

> 日期：2026-08-31  
> 状态：后台已本地实现并验证；Theme 待适配，未部署  
> 当前交付：MTM 后台与相关 API 实现；仅修改本地应用权限声明，不执行授权、数据库清理或部署。  
> 适用范围：MTM 管理后台、配置 API、数据持久化、Shopify Theme 定制器及应用配置。

## 1. 背景与目标

最新设计要求消费者在同一个步骤页面中完成多个组选项的选择，并在点击选项后切换页面顶部大图。现有 `steps → options` 模型将每组选项视为独立步骤，不能直接表达同页多个组选项。

本任务拟统一采用 `步骤 → 选项组 → 选项` 模型，代码、后台名称、API 和文档保持一致。不新增与“步骤”并列的“页面”概念：消费者看到的一页就是一个步骤。

```text
模板
└─ 步骤：西服细节（一个页面）
   ├─ 选项组：领型〔图文〕
   │  ├─ 平驳领
   │  └─ 戗驳领〔折扣展示标签〕
   ├─ 选项组：口袋〔文本〕
   │  ├─ 翻盖口袋
   │  └─ 贴袋
   └─ 选项组：其他款式〔图标＋文本，结构示例〕
      ├─ 款式一
      └─ 款式二
```

上述其他款式仅作结构示例，不增加业务选项。开衩本期不开放。

## 3. 当前实现与差距

以下为本地代码核查结果，不等于线上已验收状态。

| 能力 | 当前情况 | 本任务改造 |
|---|---|---|
| 结构 | `steps → options` | 增加 `optionGroups` 层级 |
| 选项名称、说明 | 数据与后台支持；Theme 仅显示名称 | 渲染说明并统一三种卡片布局 |
| 展示方式 | 步骤有 `displayType`，Theme 未按其区分普通选项布局 | 移至选项组，明确样式与输入行为的关系 |
| 选项图片 | 仅有 `imageUrl`，后台手填 URL，Theme 显示小圆图 | 增加素材引用和独立预览图，改用原生选择器 |
| 步骤大图 | 无配置及联动逻辑 | 新增默认图及选项点击切图 |
| 标签 | 无选项标签字段 | 新增类型与文案，前后端支持展示 |
| 默认选中 | 后台有 `defaultSelected`，Theme 未读取 | 补齐首次初始化与恢复优先级 |
| 进度与校验 | 一组选项对应一步 | 按步骤计数，按组记录选择和验证必填 |

## 4. 拟定数据模型

下述字段名称为实施建议，业务规则按已记录的 Review 结论执行，不表示已变更接口。

### 4.1 步骤 Step

- 保留稳定 `id`、`code`，以及标题、说明、启停和排序。
- 普通选项步骤增加 `optionGroups`，移除该层直接持有普通 `options` 的新版写入方式。
- 增加 `defaultPreviewImage`：步骤顶部默认大图，按已接受的缺图回退规则记为非必填。
- 刺绣、量体、Review、组合组件等特殊步骤保留其专用结构，不强制嵌套选项组。
- 不在本任务中顺带重构特殊步骤的业务能力。

### 4.2 选项组 OptionGroup

- `id`、`code`：稳定标识，不随组移动到其他步骤而改变。
- `title`、`description`：组名称及可选说明。
- `enabled`、`sortOrder`、`required`：启停、组内展示顺序与必填规则。
- `displayStyle`：建议为 `image_text`、`text`、`icon_text`。
- `options`：该组的候选选项。
- 本任务普通组选项继续采用单选，每组最多一个启用的默认选项。
- 同一模板内组编码唯一；套装中通过组件标识隔离不同子模板的选择。

### 4.3 选项 Option

- 保留 `id`、`code`、`name`、`description`、启停、排序、默认选中、适用品类等已有信息。
- `displayImage`：列表缩略图或图标，具体呈现由所属组样式决定；图文组、图标组中每个启用选项发布时必填，草稿允许缺失并提示待补齐；文本组不要求该字段。
- `previewImage`：点击后展示在步骤顶部的大图，与列表素材独立配置；允许选择同一素材复用。
- `badge`：可选对象，包含 `text` 和 `type`；当前 `type` 仅允许 `discount`。
- 未填写标签文案时不展示标签，不自动生成“10%”等折扣数字。
- 保留“不影响价格”的约束；标签不映射 Shopify Discount，也不写入价格计算逻辑。

### 4.4 素材引用

新选择的素材建议保存 `fileId`、`url` 和 `alt`，必要时保留宽高以稳定布局。Shopify 文件 ID 用于重新选择及资源核对，URL 用于预览与前台展示。

不建设旧 URL 图片的运行时兼容分支。新配置通过原生选择器建立完整素材引用；若实施时一次性导入旧素材，必须核实店铺文件关联，不能虚构文件 ID，不能核实的列为待补齐。解除关联不删除 Shopify Files 中的原文件。

## 5. 管理后台改造

1. 步骤编辑中支持默认大图，以及选项组的新增、编辑、排序、启停与删除。
2. 选项组编辑中支持名称、说明、必填、统一展示样式和候选选项管理。
3. 选项编辑中支持名称、说明、展示素材、预览大图、默认选中及标签。
4. 三类图片入口均使用 Shopify 原生文件选择器，限制图片类型，支持已有选择回填、预览、替换与解除关联。
5. 文本样式隐藏列表图片展示，但允许配置选项预览大图；切换样式不自动删除已选素材。
6. 默认选项停用、删除或跨组调整后，重新检查默认选择规则。
7. 发布校验明确指出步骤、选项组与选项的错误位置；图文组、图标组的启用选项缺少展示素材时阻止发布，旧数据如导入为草稿也必须补齐后才能发布。
8. 步骤标题、组标题、选项名称保持层级清楚，避免仍将组选项称作步骤。

## 6. 消费者端行为

### 6.1 页面、选择与校验

- 一个普通步骤渲染该步骤内全部启用选项组，各组独立单选。
- 进度条和“第几步”按实际可见步骤计数，不按组选项数量计数。
- 下一步校验当前步骤中所有可见、启用且必填的选项组，定位未完成的组。
- 服务端独立验证组与选项合法性，不信任前端传入的名称、图片、标签或价格。
- 选中边框、勾选标识和键盘操作同步表达选择状态。
- 单品与套装子模板均覆盖同页多组；不改变套装商品的交易方式。

### 6.2 图片与标签

- 首次进入显示步骤默认大图；点击任一组选项时显示该选项预览大图。
- 图文、文本、图标＋文本均支持大图联动，文本样式不依赖列表图片字段。
- 图片加载错误不得阻止选择或进入下一步，需有明确回退处理。
- 标签按后台配置显示；当前折扣类型仅提供视觉样式。
- 说明和标签作为文本安全渲染，不支持任意 HTML。

### 6.3 已接受的交互规则

- 选项缺少预览大图：回退步骤默认图；默认图也缺失时隐藏大图区域。
- 返回步骤：恢复该步骤最后查看的大图，避免多个组选项之间无法确定显示优先级。
- 无历史选择时应用各组默认选项；有有效草稿时优先恢复草稿，不覆盖用户选择。
- 即使多个组有默认选项，首次进入也显示步骤默认图，不任意选取某组大图。
- 无启用选项的组不展示；普通选项步骤没有可交互的组时跳过，并同步调整进度与校验。该规则不用于跳过没有选项组的刺绣、量体或 Review 等特殊步骤。

## 7. API、持久化与新模型切换

### 7.1 配置版本

新版模板配置使用 Schema v3，明确表达 `steps → optionGroups → options`。用户已确认不需要保留旧版本：新程序只支持 v3，不增加 v2 读取适配、双版本 API 或旧版本继续服务能力。当前代码仅支持 v2，因此运行时校验、存储读取、发布版本、前台配置解析必须同步调整。

数据库当前将配置存于模板及发布版本的 `config_json`，结构新增不一定需要拆表，但必须更新 `schema_version`，并处理切换后的商品绑定。是否需要 D1 DDL 变更，以实施前最终设计为准。新版自身的草稿、发布和版本管理继续保留；不保留的是改造前的旧模型版本。

### 7.2 配置切换与边界

- 不要求保留旧模板及其发布版本，不要求自动迁移旧配置；实施时可重建 v3 配置。若为减少录入进行一次性导入，导入结果必须通过完整 v3 校验，不成为长期兼容分支。
- 上线前盘点受影响的模板和商品绑定，将需要继续提供定制的商品绑定到已发布 v3 配置；未完成重建或绑定的商品应明确停用定制，不能让线上入口读取 v2 后报错。
- 旧色卡、下拉及普通文本输入不因历史兼容要求自动纳入新版三种组选项样式，也不能静默转换为普通文本单选。特殊步骤原有业务能力仍按第 4.1 节保留。
- 旧配置退出服务或清理必须先明确对象与影响，并准备备份、执行预检及恢复材料；本次文档更新不执行任何清理。

### 7.3 选择数据与历史业务记录

- 新版使用选项组编码作为稳定选择键，并保留组件作用域，避免组移动造成选择失效。
- 配置请求、选择校验、实例创建、Review、购物车属性及订单快照消费者统一采用新模型；旧格式请求返回明确的配置已更新提示，不作为 v3 静默处理。
- 旧浏览器定制选择草稿失效，提示按新配置重新选择；不得误清空无关量体资料。新版有效草稿仍支持恢复。
- “不保留旧版本”针对模板配置，不代表删除 Shopify 历史订单、订单快照、已有业务记录或量体资料。历史快照保持原样，不以新配置回写；本任务不保证旧定制实例可在新定制器中重新编辑。
- Shopify Line Item Properties 的消费者可读摘要应包含组名称和选项名称，不把步骤分组变化误解释为商品或价格变化。

## 9. Shopify 接入要求

- 沿用已确认的 `shopify.intents.invoke('pick:shopify/File')` 方向，选择结果读取 `response.data.ids`。
- 图片选择入口需运行在 Shopify Embedded App 环境；独立访问后台时给出明确引导，不静默退回自建素材库。
- 当前应用配置已设置 `embedded = true`，但尚未声明 `read_files`；实施时核查并补齐文件读取权限及店铺授权。
- 仅为选择和查询已有文件，不预设必须增加 `write_files`。原生弹窗内上传等行为所需权限按当时官方文档与实店验证确定。
- 所选文件需检查当前店铺归属、文件类型和可用状态；取消选择保留原值。
- Admin API 凭证只保存在服务端，不传给 Theme 或浏览器。
- 只使用公开展示素材，不把客户私密照片或量体资料存入 Shopify Files。
- 参考：[原生文件选择器公告](https://shopify.dev/changelog/intents-api-file-picker)、[Intents API](https://shopify.dev/docs/api/app-home/apis/user-interface-and-interactions/intents-api)。开发时需再次核实最新接口。

## 11. 验收标准

| 场景 | 预期结果 |
|---|---|
| 新建结构 | 一个步骤可配置至少三个组，保存、重新打开、发布后结构一致 |
| 三种样式 | 同一步骤三个组分别采用图文、文本、图标＋文本，名称和说明正确展示 |
| 大图联动 | 点击任意组选项即切换对应预览图，不修改其他组选择 |
| 缺图／失败 | 缺选项预览图回退步骤默认图，默认图缺失则隐藏大图；加载失败有回退，交互不中断 |
| 展示素材必填 | 图文组、图标组每个启用选项缺素材时阻止发布；允许保存待补齐草稿；文本组无此要求 |
| 原生选图 | 打开 Shopify 原生弹窗，确认回填、取消不修改、重新打开预选正确 |
| 权限／失效素材 | 缺权限、跨店文件、非图片、未就绪或已删除文件得到明确处理 |
| 标签 | 空标签不显示；折扣文案安全展示；商品价格、加购金额与结算金额不受影响 |
| 独立选择 | 每组单选；默认选中、启停、排序与发布规则正确 |
| 下一步 | 所有必填组完成后才可继续，错误能定位到组；进度按步骤计算 |
| 草稿／返回 | v3 有效草稿恢复不丢失选择，返回恢复该步骤大图；旧定制草稿提示失效，不清空量体资料 |
| 特殊步骤 | 刺绣、量体、Review 与现有购买流程不因新层级回归 |
| 套装 | 子模板多组正确渲染与校验，组件之间相同编码互不覆盖 |
| 交易链路 | 配置校验、实例创建、购物车摘要与订单快照保持一致 |
| 配置切换 | 新程序只接受 v3，旧格式有明确处理；受影响商品完成新绑定或停用定制，无残留 v2 在线依赖 |
| 业务边界 | 不渲染 A／C／E 标记、不开放开衩；历史订单与快照不被删除或改写 |
| 移动端／可访问性 | 图片不撑破布局，长文案可读，键盘可选择并辨识选中状态 |

管理端改造后按届时项目 scripts 执行 lint、类型检查及生产构建；配置切换和服务端校验增加有针对性的测试，不能仅以构建通过代替业务验收。Theme 执行项目可用的主题检查并进行真实店铺人工联调。
