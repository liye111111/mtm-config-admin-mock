# 刺绣／绣字定制项开发任务

## 1. 任务信息

- 状态：Admin、Theme 与 Storefront API 已完成；待部署测试环境并执行 Shopify 实店 UAT
- 优先级：P1（以最终确认的一期范围为准）
- 涉及项目：`mtm-config-admin-mock`、`shopify-theme-poc`
- 目标：允许运营人员在模板中配置刺绣步骤，消费者填写刺绣文字并完成校验、Review、加购和订单数据保存
- 价格基线：建议一期不改变 Shopify 商品价格，与当前 `pricingMode: "none"` 保持一致

## 2. 背景与现状

当前模板已经支持：

- `options` 类型的定制步骤；
- `displayType: "text_input"` 配置值；
- 步骤启用、必填、说明和排序；
- 普通候选选项、图片和排序；
- Storefront 草稿、Review、服务端校验、定制实例及订单关联。

但 `text_input` 目前只是后台可选择的展示类型，尚未形成完整行为：

- Theme 仍把所有 `options` 步骤渲染为按钮列表；
- 前端状态没有独立文本输入处理和字符提示；
- 服务端把步骤值当作候选选项编码校验；
- 模板没有文本长度、字符范围、占位文案等输入规则；
- Review、摘要和订单链路未按刺绣文字处理；
- 当前价格模型明确不支持定制加价。

因此，本任务不是新增服装“品类”，而是在既有模板中新增一个 `embroidery` 专用复合步骤。是否刺绣、位置、字体、颜色和文字在同一消费者步骤内完成，不再拆分为多个步骤，也不使用通用步骤显示条件。

## 3. 建议的一期范围

### 3.1 包含范围

1. 后台可以在任意适用模板中添加一个刺绣步骤；
2. 步骤使用 `type: "embroidery"`；
3. 后台可以配置：
   - 步骤名称、稳定编码、说明、排序；
   - 是否启用、是否必填；
   - 最小和最大字符数；
   - 输入框占位文案；
   - 允许的字符规则；
4. Theme 根据 `embroidery` 渲染包含开关、位置、字体、颜色和文字的复合组件；
5. 输入时显示字数，并保存／恢复当前会话草稿；
6. 前端执行即时校验，服务端执行相同或更严格的权威校验；
7. Review 显示刺绣文字；
8. 定制实例保存刺绣原文快照；
9. 购物车显示摘要，订单通过 `_mtm_customization_id` 关联完整配置快照；
10. 单品模板和组合模板的组件子模板均可使用刺绣步骤；
11. 桌面端与移动端均可完整输入、修改和提交。

### 3.2 固定刺绣字典

首期使用代码内置默认值，并随模板发布快照返回；后台只读展示，不逐项维护：

- 位置：西服内侧、左袖口、右袖口；
- 字体：标准体、手写体、衬线体；
- 颜色：黑色、藏青色、银灰色、金色。

后续将这些选项迁移到 D1 字典表，并提供独立维护界面。迁移时保持编码稳定，历史模板继续使用发布时快照。

### 3.3 不包含范围

- 刺绣图案上传或图片上传；
- 实时刺绣效果预览、字体渲染或 3D 预览；
- 多行富文本；
- 自动翻译、敏感词审核或人工审核流程；
- 动态加价、折扣、附加商品或 Shopify 成交价修改；
- ERP／MTM 新接口及生产指令字段映射；
- 通用的步骤显示／隐藏规则编辑器；
- 同一步骤内无限增加多组刺绣内容。

上述能力如需纳入，应重新确认数据结构、交互和工作量。

## 4. 数据模型设计

### 4.1 保持现有步骤类型

新增 `embroidery` StepType，使用一个复合步骤：

```json
{
  "id": "embroidery_text",
  "code": "embroidery",
  "title": "刺绣定制",
  "description": "请输入需要刺绣的文字",
  "type": "embroidery",
  "required": false,
  "enabled": true,
  "sortOrder": 8,
  "options": [],
  "embroidery": {
    "positions": [{ "code": "inside_jacket", "name": "西服内侧" }],
    "fonts": [{ "code": "standard", "name": "标准体" }],
    "colors": [{ "code": "black", "name": "黑色" }]
  },
  "textInput": {
    "minLength": 0,
    "maxLength": 20,
    "placeholder": "请输入刺绣文字",
    "characterPolicy": "letters_numbers_spaces"
  }
}
```

原因：

- 消费者只经历一个刺绣步骤；
- “无需刺绣”仅收起当前组件内部字段，不改变全局步骤流；
- 默认字典随模板版本形成稳定快照；
- 输出仍使用五个稳定业务字段，便于购物车、订单和未来 ERP 对接。

### 4.2 文本规则

建议为 `CustomizationStep` 增加可选的 `textInput`：

```ts
type TextInputConfig = {
  minLength: number;
  maxLength: number;
  placeholder?: string;
  characterPolicy: "letters_only" | "letters_numbers_spaces" | "unicode_text";
};
```

约束：

- 只有 `type === "options" && displayType === "text_input"` 时允许配置 `textInput`；
- 文本输入步骤不使用 `options`，发布时应要求 `options` 为空；
- `maxLength` 必须大于等于 `minLength`，并设置系统安全上限；
- 选填步骤允许空字符串；非空时仍执行字符和长度校验；
- 服务端按 Unicode 字符数量校验，不按 UTF-16 字节长度校验；
- 保存前进行首尾空白清理，但不擅自改变用户文字大小写；
- HTML 输出始终转义，不将输入作为 HTML 渲染。

### 4.3 兼容性

- `textInput` 为可选字段，现有 Schema v2 模板可以继续读取；
- 非文本步骤不受影响；
- 已发布模板继续作为不可变版本保存；
- 若 Zod 使用默认值补齐旧配置，不应在读取时意外修改已发布版本；
- 不需要新增数据库列，完整配置继续存放在模板 JSON 和定制实例选择快照中。

## 5. Admin 管理端工作项

涉及 `mtm-config-admin-mock`：

1. 扩展 Domain 与 Zod Schema，增加 `TextInputConfig`；
2. 当展示方式选择“文本输入”时：
   - 隐藏普通候选选项编辑器；
   - 显示最小字符数、最大字符数、占位文案和字符规则；
3. 切换到文本输入时，要求运营确认或自动清除已有候选选项；
4. 切换回单选／图片卡片等展示方式时，清除无效的 `textInput` 配置；
5. 模板发布校验应拒绝：
   - 文本规则缺失或范围非法；
   - 文本输入步骤仍包含候选选项；
   - 非文本步骤携带文本规则；
6. JSON 预览和发布版本记录应完整显示文本规则；
7. 如有模板复制功能，文本规则应一并复制。

## 6. Theme 前端工作项

涉及 `shopify-theme-poc`：

1. 动态步骤渲染器按 `displayType` 分派组件；
2. 为 `text_input` 渲染：
   - 可访问的 `label`；
   - 单行文本输入框；
   - 占位文案；
   - 最大字符限制；
   - 当前字数／最大字数提示；
   - 就地错误提示；
3. 使用 `input` 事件更新 `customSelections[step.code]`；
4. 输入变化后调用现有 `saveDraft()`；
5. `restoreDraft()` 后恢复输入框内容；
6. `validateStep()` 根据必填、字符数和字符规则校验；
7. `syncControls()` 同时同步按钮选择和文本输入；
8. `renderReview()` 对文本步骤直接显示用户文字，不调用 `optionName()`；
9. 组合模板的组件步骤保存到对应 `componentSelections[component.code][step.code]`；
10. 对所有动态输出执行 HTML 转义；
11. 补充移动端输入框、字数提示、错误提示和软键盘场景样式。

## 7. Storefront API 与服务端校验

服务端必须将文本输入和普通候选选项分开校验。

对于 `displayType === "text_input"`：

1. 从 `selections[step.code]` 或组件选择中读取字符串；
2. 拒绝对象、数组、数字等非字符串输入；
3. 根据步骤配置执行 trim、必填、长度和字符规则校验；
4. 限制请求体及单字段最大长度，防止超大输入；
5. 摘要使用“步骤名称：用户文字”的可读形式；
6. 完整原文保存在 `selection_snapshot_json` 或组件快照；
7. 日志和错误监控不记录刺绣原文；
8. 服务端生成购物车属性，浏览器不得自行构造可信摘要。

普通选项步骤继续执行候选选项编码校验，不能把任意字符串当作合法选项。

## 8. Review、购物车与订单数据

### 8.1 Review

Review 至少显示：

```text
刺绣服务：需要
刺绣位置：西服内侧
刺绣字体：手写体
刺绣颜色：银灰
刺绣文字：LI YE
```

没有填写的选填文本步骤不显示或显示“未选择”，具体样式沿用现有 Review 规范。

### 8.2 Line Item Properties

继续采用精简属性：

```json
{
  "定制摘要": "…… / 刺绣文字：LI YE",
  "_mtm_customization_id": "cust_...",
  "_mtm_template": "mens_suit@4"
}
```

如果摘要可能超过 Shopify 属性的实用展示长度，应只保留主要可见信息，完整内容以 `_mtm_customization_id` 对应的不可变快照为准。

### 8.3 订单

- Shopify Order Line Item 继承 Line Item Properties；
- `orders/create` Webhook 根据 `_mtm_customization_id` 关联定制实例；
- 历史订单按下单时模板版本和选择快照解释；
- 模板后续修改不得覆盖历史刺绣内容。

## 9. 价格处理

最新需求说明约定一期定制选择不改变商品价格，当前系统也限定：

```text
pricingMode = none
affectsPrice = false
```

因此建议本任务一期行为为：

- Review 继续显示 Shopify Variant 成交价格；
- 刺绣选择和文字不加价；
- 不新增价格计算或价格明细；
- 后台不展示可编辑刺绣费用，避免配置与成交价不一致。

SOW 中“依据收费标准实现”与最新一期“不加价”口径存在差异。若确认刺绣必须收费，应暂停本任务当前方案，先独立设计受 Shopify 约束的定价及下单模型。

## 10. 安全与隐私

- 刺绣文字属于用户输入，所有展示位置必须转义；
- 禁止使用 `innerHTML` 拼接未经转义的原文；
- 限制文本长度、请求体大小和提交频率；
- 服务端错误信息不回显内部规则实现或完整请求；
- 日志、Webhook 处理日志和监控事件不记录刺绣原文；
- 不将刺绣文字写入 Product、Variant 或 Metafield；
- 完整内容只进入该次购买的配置实例和订单快照。

## 11. 验收标准

### 11.1 后台

- 可新增、编辑、排序、启停文本输入步骤；
- 可配置必填、字符长度、占位文案和字符规则；
- 非法规则无法保存或发布；
- 已发布配置通过 Storefront API 正确返回；
- 普通选项步骤行为不受影响。

### 11.2 Theme

- 商品绑定对应模板后，刺绣输入步骤按排序显示；
- 输入、返回、关闭重开和刷新当前会话后内容可恢复；
- 必填、长度和字符规则提示清晰；
- Review 展示内容与最终提交内容一致；
- 单品和组合模板均正确保存刺绣文字；
- 桌面端和移动端均可完成输入、切换步骤和提交；
- 输入 `<script>`、引号、emoji 和中英文边界值时页面不会执行脚本或损坏布局。

### 11.3 API、购物车和订单

- 服务端拒绝空必填值、超长值、非法字符和错误数据类型；
- 绕过前端直接提交非法文字时仍被拒绝；
- 定制实例包含正确的文本及模板版本快照；
- 购物车显示正确摘要并保留内部关联字段；
- 不同刺绣文字形成不同配置实例；
- `orders/create` 能关联对应配置实例；
- 模板更新后仍可还原历史订单中的刺绣内容。

## 13. 上线与回滚

上线顺序建议：

1. 部署 Admin/API；
2. 部署支持 `text_input` 的 Theme；
3. 在测试模板中新增并发布刺绣步骤；
4. 绑定测试商品并完成 UAT；
5. 再发布正式商品模板。

回滚顺序：

1. 停用或回滚包含刺绣步骤的模板版本；
2. 回滚 Theme 资产；
3. 必要时回滚 Admin/API；
4. 不删除已产生的定制实例和订单快照。

## 14. 已确认业务规则

2026-08-07 已确认：

1. 一期刺绣不加价；
2. 最小和最大字符数由后台配置；
3. 允许中文、英文、数字、空格和标点；
4. 允许 emoji，默认字符策略为全部 Unicode；
5. 需要“无需刺绣／需要刺绣”开关；
6. 需要刺绣位置、字体和颜色；首期使用系统默认字典，后续迁移到 D1 字典表；
7. 选择“无需刺绣”后在同一步骤内收起位置、字体、颜色和文字输入；
8. 刺绣信息需要在购物车直接显示；
9. 用户看到的一个刺绣步骤对应一个订单私有属性 `_embroidery`，值为 JSON 字符串，包含 `schemaVersion`、`stepCode`、`enabled`、`position`、`font`、`color`、`text`；位置、字体和颜色保存稳定编码，文字保存用户输入。组合商品使用 `_mtm_{组件编码}_embroidery`；
10. 单件商品只允许一处刺绣；
11. 刺绣作为一个专用复合步骤，不增加通用步骤显示条件。

开发顺序：先完成 Admin 的模型、默认字典、发布校验和编辑界面，确认后再开发 Theme 与 Storefront 的复合组件、校验和订单摘要。
